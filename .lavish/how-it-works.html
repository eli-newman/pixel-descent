Pixel Descent - how it works

34 source files. Solid arrows: depends on. Dashed: setup or read-only access. Yellow boxes are the hubs.

Every update (120 per second) and every frame

Loop→Game.update(STEP)→Controls: Input.drain()→Sim.step()→events→Feedback: sound, toasts, spray→runReport when a run ends

Loop, once per display frame→SceneRenderer.render(view)→renderUi→putImageData to canvas

What enforces this

  • eslint.config.js fails on an import that crosses a layer the wrong way.
  • state/view.ts makes a render write a compile error. A cast could still get around it.
  • tests/render.test.ts fails on any pixel change in 32 golden frames.
  • npm run build runs the tests. GitHub CI also runs the browser smoke test.
