# src/state

Everything around the sim: which screen you are on, menus, lifetime progress and saving.

| File           | Job                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `game.ts`      | `Game`: runs and their phases (title, playing, paused, crashed, over), the camera, and what each frame steps. Owns the `Sim`, `Controls`, `Feedback`, `BrakeSpray`, `CarveCloud`, particles and puffs. Implements `GameView`. Holds the tutorial `lesson`: `begin` shows the steering lesson and every step may stop the run on the next one (`nextLesson`); while a lesson is up nothing steps or animates, and `dismissLesson` goes on once it has been up `LESSON_GUARD` seconds. Showing a lesson marks it seen in `Stats.lessons` and saves. Draws between steps: `setBlend(alpha)` before each render gives `camYi` (whole pixel, floored), `camFrac` and `riderX`/`riderY` at the screen's moment, from the camera and rider before and after the latest step.                |
| `controls.ts`  | `Controls`: taps, keys and buttons turned into actions (`press`, `handleInput`), the menu position (screen, score tab, focus), settings toggles, queued tricks and flips, and the grab (`input.grab()`, with `input.setAir` told each step whether the rider is airborne, from `ControlsHost.airborne`). Under a tutorial lesson a tap, Space, Enter, T or a flip key goes on (`onLesson`); pause, mute and the setting keys still work. Talks to the game through the narrow `ControlsHost`.                                                                                                                                                                                                                                                                                        |
| `feedback.ts`  | `Feedback`: sim events turned into sound, toasts, haptics and hit-stop. Owns the toasts and the hit-stop timer. Trick landings are named in one toast ("360 BACKFLIP GRAB +pts"); a grab that counts says "GRAB!" and a landing still grabbing "STILL GRABBING". A jump line goes on the landing toast's second line (`Toast.sub`: "LINE X1.5", "LINE BROKEN"); a clean line takes the top line ("LINE CLEAN +pts") with the landing under it; a skipped kicker says "LINE MISSED".                                                                                                                                                                                                                                                                                                  |
| `runReport.ts` | Pure helpers for a finished run: `summarizeRun`, `recordRun` (scoreboard and lifetime progress), `toCard` (with the kit, so the share text can say "on skis"), `dayString`, and the `RunResult` type.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `telemetry.ts` | Pure builders for the analytics events (`runStartEvent`, `runEndEvent`, `shareEvent`) and their coarse bands (`distBucket`, `scoreBucket`, `runBucket`, `setupLabel`). Properties go most important first, because the plan may keep only two.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `tutorial.ts`  | The first-run tutorial: `LessonId` (steer, crash, slow, star, jump for a kicker, cliff), `lessonLines` (two or three short lines, touch or keys), `nextLesson` (the nearest thing ahead between `LESSON_AHEAD_MIN` and `LESSON_AHEAD_MAX` px whose lesson has not been shown, after `LESSON_FREE_RIDE`; a bush is a slow lesson, anything else solid a crash one, pebbles none), `tutorialOn` (only while `Stats.runs` is under `TUTORIAL_RUNS` and a lesson is left), `markSeen`, `lessonSeen`, `ALL_LESSONS`. Pure: reads the sim view, never changes it.                                                                                                                                                                                                                          |
| `view.ts`      | `GameView` (with the tutorial `lesson`), `SimView`, `DeepReadonly`: the read-only types that are all `render/` may see.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `menu.ts`      | Button layout (`menuButtons`) shared by `controls.ts` and `render/ui.ts`, plus the `Phase` and `Screen` types. The title, score tabs and kit tabs use a wider grid (80 px buttons, 8 px from the edges) than pause and game over, so their labels fit at twice the font size.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `progress.ts`  | Lifetime stats, achievements, challenges, unlockable gear. `Gear.kit` is `'snowboard'` or `'skis'`, open to everyone and only a look (the sim never sees it). Pure data and rules, no storage. `Stats.lessons` holds one bit per tutorial lesson already shown; older saves load it as 0 (and their old `hintRuns` is dropped), and a player with `TUTORIAL_RUNS` runs or more never sees a lesson.                                                                                                                                                                                                                                                                                                                                                                                  |
| `storage.ts`   | `Store`: localStorage for scores (all-time top 10, today's daily top 10, best), settings, progress. Every call guarded. Per-seed boards in older saves are merged into the all-time board on load, keeping the newest daily board. Old `ghost:*` keys are deleted when a `Store` is built. Old `gates` and `ghosts` fields are dropped the next time that data is saved. An earned `photo` achievement stays in the save. A save without `gear.kit` (or with an unknown one) rides a snowboard.                                                                                                                                                                                                                                                                                      |
| `effects.ts`   | Fixed particle pool, brake spray and the carve cloud. Flecks that come down leave grains on the snow (every other one, in a fixed ring of 320), cleared on a new run. `Puffs` is a fixed pool of 160 soft round clouds that grow and thin out over their life. `CarveCloud` throws them from the board when the rider carves hard at speed (`CarveCloud.power`: from `CLOUD_MIN_SPEED` up, more for a harder turn and for speed scrubbed on the edge, none in the air or braking): out of the turn, and moving at only a share of the rider's speed so the cloud hangs behind him. Running straight it still leaves a lighter wake (`CarveCloud.wake`, up to `WAKE_POWER`, growing with speed squared) spilling out to both sides. Cosmetic only, from the game's own random source. |

## Rules

- May import `../sim` and `../core`. From `render/` and `platform/` only types: `Sfx`, `Input`, `share` and `analytics` arrive through `GameDeps` in `main.ts`. Boundary lint enforces this.
- Analytics: `Game.begin` sends Run Start and `Game.finish` sends Run End through `GameDeps.analytics` (the share event is sent in `main.ts`, which knows how the share went). `runsStarted` counts runs since the page loaded and is never stored. Never put a seed, an exact score, a time or anything that could identify a player in an event, and never let analytics touch the sim.
- `Controls` does not import `Game`: anything it needs from the game goes on `ControlsHost`. Keep it narrow.
- Anything new that `render/` must read goes on `GameView` in `view.ts`, as data. Never put a mutating method on a view.
- Retiring an achievement: delete it from `ACHIEVEMENTS`. Saves keep the old id, and `Game.achievementCount` only counts ids that still exist.
- The GEAR screen's rows top to bottom are BOARD / SKIS (two buttons like the score tabs, the chosen one yellow), the board look, then the rider look. Left and right on the keyboard change the row the focus is on, so `cycleFocusedGear` maps focus 0-1, 2-3 and 4-5 to those rows: keep it in step with `GEAR` in `menu.ts`.
- `Settings.color` (off by default, older saves load it off) switches the colour look. It is toggled by the `color` button on the title screen (beside DAILY) and in the pause menu, and is read only by `render/`.
- The tutorial never touches the sim: a lesson only stops `Game` from stepping it, so a run plays out the same with or without lessons (`tests/tutorial.test.ts`). Tests' `makeGame` plays as a player who has had the tutorial unless asked for a new one.
- Saved data lives under `SAVE_PREFIX` in `core/config.ts`. Changing the shape of stored data needs a migration or a version bump.
- Adding a menu button: update `ButtonId` and `menuButtons` in `menu.ts`, add it to the `onButton` table in `controls.ts`, draw it in `render/ui.ts`. `onButton` and `onAction` are `Record`s, so a new id or action does not compile until it is handled.

## Keeping docs in sync (mandatory)

When you change anything in this folder (add, remove, rename a file, change an exported function, constant or rule), update this file in the same change. Update the root `CLAUDE.md` too if the layout or dependency rules move, and `README.md` if player-facing behavior or paths change.
