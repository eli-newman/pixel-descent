# src/state

Everything around the sim: which screen you are on, menus, lifetime progress and saving.

| File           | Job                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `game.ts`      | `Game`: runs and their phases (title, playing, paused, crashed, over), the camera, and what each frame steps. Owns the `Sim`, `Controls`, `Feedback`, `BrakeSpray` and particles. Implements `GameView`.                                                                                                                                                                                                                                                                                        |
| `controls.ts`  | `Controls`: taps, keys and buttons turned into actions (`press`, `handleInput`), the menu position (screen, score tab, focus), settings toggles, queued tricks and flips. Talks to the game through the narrow `ControlsHost`.                                                                                                                                                                                                                                                                  |
| `feedback.ts`  | `Feedback`: sim events turned into sound, toasts, haptics and hit-stop. Owns the toasts and the hit-stop timer.                                                                                                                                                                                                                                                                                                                                                                                 |
| `runReport.ts` | Pure helpers for a finished run: `summarizeRun`, `recordRun` (scoreboard and lifetime progress), `toCard` (with the kit, so the share text can say "on skis"), `dayString`, and the `RunResult` type.                                                                                                                                                                                                                                                                                           |
| `telemetry.ts` | Pure builders for the analytics events (`runStartEvent`, `runEndEvent`, `shareEvent`) and their coarse bands (`distBucket`, `scoreBucket`, `runBucket`, `setupLabel`). Properties go most important first, because the plan may keep only two.                                                                                                                                                                                                                                                  |
| `view.ts`      | `GameView`, `SimView`, `DeepReadonly`: the read-only types that are all `render/` may see.                                                                                                                                                                                                                                                                                                                                                                                                      |
| `menu.ts`      | Button layout (`menuButtons`) shared by `controls.ts` and `render/ui.ts`, plus the `Phase` and `Screen` types.                                                                                                                                                                                                                                                                                                                                                                                  |
| `progress.ts`  | Lifetime stats, achievements, challenges, unlockable gear. `Gear.kit` is `'snowboard'` or `'skis'`, open to everyone and only a look (the sim never sees it). Pure data and rules, no storage. `Stats.hintRuns` counts finished runs for the first-run slope labels; older saves load it as 0.                                                                                                                                                                                                  |
| `storage.ts`   | `Store`: localStorage for scores (all-time top 10, today's daily top 10, best), settings, progress. Every call guarded. Per-seed boards in older saves are merged into the all-time board on load, keeping the newest daily board. Old `ghost:*` keys are deleted when a `Store` is built. Old `gates` and `ghosts` fields are dropped the next time that data is saved. An earned `photo` achievement stays in the save. A save without `gear.kit` (or with an unknown one) rides a snowboard. |
| `effects.ts`   | Fixed particle pool and brake spray. Flecks that come down leave grains on the snow (every other one, in a fixed ring of 320), cleared on a new run.                                                                                                                                                                                                                                                                                                                                            |

## Rules

- May import `../sim` and `../core`. From `render/` and `platform/` only types: `Sfx`, `Input`, `share` and `analytics` arrive through `GameDeps` in `main.ts`. Boundary lint enforces this.
- Analytics: `Game.begin` sends Run Start and `Game.finish` sends Run End through `GameDeps.analytics` (the share event is sent in `main.ts`, which knows how the share went). `runsStarted` counts runs since the page loaded and is never stored. Never put a seed, an exact score, a time or anything that could identify a player in an event, and never let analytics touch the sim.
- `Controls` does not import `Game`: anything it needs from the game goes on `ControlsHost`. Keep it narrow.
- Anything new that `render/` must read goes on `GameView` in `view.ts`, as data. Never put a mutating method on a view.
- Retiring an achievement: delete it from `ACHIEVEMENTS`. Saves keep the old id, and `Game.achievementCount` only counts ids that still exist.
- The GEAR screen's rows top to bottom are SNOWBOARD / SKIS (two buttons like the score tabs, the chosen one yellow), the board look, then the rider look. Left and right on the keyboard change the row the focus is on, so `cycleFocusedGear` maps focus 0-1, 2-3 and 4-5 to those rows: keep it in step with `GEAR` in `menu.ts`.
- `Settings.color` (off by default, older saves load it off) switches the colour look. It is toggled by the `color` button on the title screen (beside DAILY) and in the pause menu, and is read only by `render/`.
- Saved data lives under `SAVE_PREFIX` in `core/config.ts`. Changing the shape of stored data needs a migration or a version bump.
- Adding a menu button: update `ButtonId` and `menuButtons` in `menu.ts`, add it to the `onButton` table in `controls.ts`, draw it in `render/ui.ts`. `onButton` and `onAction` are `Record`s, so a new id or action does not compile until it is handled.

## Keeping docs in sync (mandatory)

When you change anything in this folder (add, remove, rename a file, change an exported function, constant or rule), update this file in the same change. Update the root `CLAUDE.md` too if the layout or dependency rules move, and `README.md` if player-facing behavior or paths change.
