# src/platform

The edge of the game: everything that talks to the browser. Keep browser APIs in this folder so `sim/` and `state/` stay testable.

| File           | Job                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `input.ts`     | Keyboard, mouse, touch and swipe turned into `Action`s and taps, a held-steer value and the grab (`grab`, `setAir`). Cancels browser zoom gestures. `usingTouch` starts true where the main pointer is a finger (`pointer: coarse`), so a phone shows the touch help before its first touch.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `loop.ts`      | Fixed 120 Hz update with a requestAnimationFrame render. `render` gets `alpha`: how far the moment on screen lies between the last step and the next (0 to 1).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `viewport.ts`  | `fitCanvas`: where the 180x320 frame goes and at what scale. On a phone held upright (`fill`) it fills the screen's width (the scale can be fractional) with its top just under the notch; otherwise the largest whole scale that fits, with safe-area margin. `above` and `below` are the whole rows of slope to draw past the frame so it reaches the screen's edges (at most `MAX_EXTRA_ROWS`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `present.ts`   | Puts the two layers on their canvases. Each canvas's backing is exactly the device pixels it covers (`LayerBox`: `slopeBox` for the slope, from `above` rows over the frame to past the screen's bottom, starting on a whole device pixel with the picture `dy` lower inside it; `frameBox` for the HUD, exactly the frame), so the page shows it pixel for pixel (`image-rendering: pixelated`) and no browser filter touches it. `SharpCanvas` does the scaling itself: at a fractional scale it blows the picture up by the whole number `sharpScale` (7 for a 6.55 phone scale) and shrinks that to the canvas with one bilinear pass (`imageSmoothingQuality: 'low'`), so every pixel stays the same size wherever it is and each edge softens by at most one device pixel, where a plain stretch by 6.55 makes rows 6 or 7 pixels tall and art changes shape as it scrolls; at a whole scale it blows the picture straight up with no smoothing. Letting the browser do the shrink instead looked blurry on a real phone, though not in headless screenshots: how a browser filters a scaled canvas on screen is its own choice. `draw` skips a picture identical to the last one (an unchanged HUD). `slideRows` is the device pixels to slide the picture up for the camera's fraction of a pixel, drawn into the same canvas. |
| `audio.ts`     | Procedural WebAudio (wind, carve hiss, rumble, pitch ladders, music).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `shareDom.ts`  | Web Share / clipboard / download flow for a dare (`shareResult(dare, siteUrl)`): the dare card image (`cardCanvas`), the dare's words and its `/c/<code>` link. Resolves to a `ShareOutcome`: the player's message and the `via` analytics reports.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `analytics.ts` | Vercel Web Analytics without the npm package: `startWebAnalytics` queues a `beforeSend` (`cleanUrl`), adds the script tag and returns a `Tracker`; `analyticsConfig` reads Vercel's build-time paths; `trimProps` keeps the first `ANALYTICS_MAX_PROPS`; `noTracker`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |

## Rules

- May import `../core` and `../render/share` and `../render/framebuffer` (for the card). Not `sim/`, not `state/` except types.
- `Game` never imports from here at runtime. It receives `Sfx` and `Input` as dependencies built in `main.ts`.
- Smooth motion on any refresh rate: the sim steps at a fixed 120 Hz, and a 60, 90 or 120 Hz screen gets those steps unevenly (at 90 Hz: 1, 1, 2). So the game draws the camera and rider between steps at `alpha` (`Game.setBlend`), and the page draws the slope in two layers: `#game`, which runs past the frame to the screen's edges plus one spare row and is slid up by `slideRows` for the leftover fraction of a pixel, and `#ui` (HUD, menus, toasts) on top, which never moves and lets touches through. The slide is drawn into the slope canvas's own pixels, never a CSS transform: a transform and the canvas pixels it moves can reach the screen a frame apart, which jerks the slope by a pixel at speed. Both canvases are drawn at the screen's own resolution, so each changed frame costs one small upload, one nearest-neighbour blow-up and one bilinear shrink per layer. This holds 60 fps riding on an emulated iPhone (1179 by 2568 device pixels) in headless Chromium and WebKit; an earlier version that drew the same way ran at 20 fps in a software-rendered browser, so measure again after changing it. Never hand the final scaling back to the browser: that was the blurry phone picture. Measure motion with a fake display (see `tests/loop.test.ts`), not by eye on a 60 Hz desktop.
- The page must never zoom, and a zoom must never resize the game. iOS Safari ignores `user-scalable=no`, so `input.ts` cancels pinches and the end of every touch outside a button (a double tap would otherwise zoom). `main.ts` sizes the game from `documentElement.clientWidth` and `clientHeight`, because `innerWidth` and `innerHeight` shrink while iOS Safari is zoomed. Desktop emulators do not show this: check it in the iOS Simulator or on a phone.
- Touch gestures (`input.ts`): a finger holds its half of the screen only after `HOLD_MS` still (or `SWIPE_MS` of moving without a flick), never at once, because in the air even one step of hold commits a half turn and every swipe would start with a spin. A quick flick is vertical (a flip) unless its sideways part is more than `SWIPE_SLANT` times its vertical part, so a slanted thumb flick down is still the FRONTFLIP and only a clearly sideways one is a spin. A vertical flick (`FLIP_SWIPE_MIN` px within any `SWIPE_MS` of the touch) also counts after resting the thumb; a sideways one only within `SWIPE_MS` of touching, so a steering drag never spins. Swipe down sends `down`, which is flip 1, shown as FRONTFLIP (see the flip naming note in `src/sim/CLAUDE.md`). The hold is timed on the `now` clock passed to `Input` (`performance.now()` in the browser), flicks on event `timeStamp` differences, so the two clocks never mix.
- Two thumbs (`input.ts`): any two fingers down are the brake (the slip slide), however far apart in time they land, so holding one side and then pressing the other side slides. The first finger stays the tracked one, and when the tracked finger lifts, `takeOver` hands steering at once to the newest finger still down, as a hold (never a flick): rolling off one thumb of the brake turns toward the other. Every finger's position is tracked in `touches` for this. Before `takeOver`, the finger left down was ignored until lifted, so a turn did not register.
- Grabs (`input.ts`): X or Shift held is a grab. On touch (one thumb), a still touch in the air lifted within `TAP_MS` grabs, and stays grabbed until the next touch lands (it lets go on touch down, not lift, so a late tap still lets go before touchdown; lifting that touch quickly does not grab again) or the game says the rider is down (`setAir(false)`). So a tap never spins, a new still touch in the air holds its side only after `TAP_MS` instead of `HOLD_MS`. Flicks, drags and two fingers never grab.
- Every browser API call that can throw (storage, vibrate, share, audio context, analytics) must be guarded.
- Analytics never throws, never waits and never sees a seed: `cleanUrl` drops the hash and every query value but `utm_*` from every page view and event, cuts a dare path (`/c/<code>`, which holds a seed) back to its folder, a visit from a shared link is reported as `<dir>/from-share`, the queue stops at `MAX_QUEUE` while the script loads, and a script that fails to load (an ad blocker, a host that is not Vercel) turns tracking into a no-op. The Vercel docs limit event properties to flat strings, numbers and booleans, 255 characters each, and 2 per event on Pro (8 with Web Analytics Plus); Hobby has no custom events, only page views.
- `vite.config.ts` bakes `__ANALYTICS__` into the bundle: null unless `VERCEL=1` (every Vercel build) or `VITE_ANALYTICS=1`. With `VITE_ANALYTICS=1 npm run dev` it loads Vercel's debug script, which logs to the console and sends nothing. `VERCEL_OBSERVABILITY_CLIENT_CONFIG` (Vercel sets it on every build of this project) supplies a per-project script and endpoint path that ad blockers do not know, given without a leading slash (`76b40da1c7a41f39/script.js`): `analyticsConfig` makes it root-relative and ignores anything that is not a plain path on this site. Without it, `/_vercel/insights/script.js`.

## Keeping docs in sync (mandatory)

When you change anything in this folder (add, remove, rename a file, change an exported function, constant or rule), update this file in the same change. Update the root `CLAUDE.md` too if the layout or dependency rules move, and `README.md` if player-facing behavior or paths change.
