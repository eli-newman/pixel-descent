# src/sim

The rules of the game as pure, deterministic code. Feed a seed and inputs at the fixed step and it always plays the same run. The live game and the tests both run it.

| File            | Job                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sim.ts`        | `Sim` class: one world step (`step(input, dt)`), emits `events` (crash, star, trick, ...). The hub of this folder.                                                                                                                                                                                                                                                                                                                  |
| `rider.ts`      | `stepRider`: heading spring, braking, movement, slope walls. Also `launch`, `riderZ`, `headingY`, `headingAngle`.                                                                                                                                                                                                                                                                                                                   |
| `riderState.ts` | `RiderState` (including `stance`: regular or switch, and the grab: `grab`, `grabT`, `grabDone`), `Face`, `createRider`. Types and the starting state only.                                                                                                                                                                                                                                                                          |
| `speed.ts`      | The speed model: `cruiseSpeed`, `topSpeed`, tuck and scrub (`stepSpeed`), air time and flight distance. The spawner's only rider dependency, so it must stay exact arithmetic.                                                                                                                                                                                                                                                      |
| `tricks.ts`     | Spins, flips and grabs: assisted and manual stepping, caps, `startTrick`/`startSnap`/`startFlip`, `stepGrab`/`resetGrab`, landing tolerances, `GRAB_MIN`, `GRAB_BAIL_SPIN`.                                                                                                                                                                                                                                                         |
| `pose.ts`       | `RiderPose` and `poseOf`: what the renderer needs to draw the rider, including the stance and `grab`. `heelSide` says which side of the rider shows.                                                                                                                                                                                                                                                                                |
| `landing.ts`    | `touchDown`: judges a landing (clean, sloppy, bail, including still grabbing), swaps the stance after an odd number of half turns, pays the score, returns the `LandEvent`.                                                                                                                                                                                                                                                         |
| `world.ts`      | Live object lists: adding spawned batches, culling, ramp crossing (`WorldLists`, `addBatch`, `cullAbove`, `takeRamp`).                                                                                                                                                                                                                                                                                                              |
| `collision.ts`  | Hitbox overlap tests and near-miss rules. Every obstacle with a box crashes the rider, bushes included, and counts for close calls. `isPebble` / `PEBBLE_SIZE`: rocks below it never collide, and the renderer draws them flat by the same rule.                                                                                                                                                                                    |
| `lines.ts`      | `LineTracker`: the jump line being ridden. Pays `lineMult` (x1, x1.5, x2) on each clean landing's trick points and `LINE_BONUS` per kicker for a clean line, and emits `LineEvent` (building, done, or broken by a sloppy landing or a skipped kicker).                                                                                                                                                                             |
| `score.ts`      | Points, combos, near-miss rewards, spin, flip and grab points (`grabPoints`, `addGrab`, `GRAB_BASE`, `GRAB_PER_S`, `GRAB_COMBO`).                                                                                                                                                                                                                                                                                                   |
| `trail.ts`      | Fixed-size ring buffer of board positions (allocation-free).                                                                                                                                                                                                                                                                                                                                                                        |
| `spawner.ts`    | Deterministic endless course generator (trees, rocks, bushes, lane stars, kickers, jump lines, risk lanes) with a guaranteed-open path. Ice and deep snow were removed (tags `archive/ice`, `archive/deep-snow`); `planPatches` still makes their draws and the jump planning they triggered, so courses did not change. Jumps and lanes are planned together in `planFeatures`; `lineChance` is the chance a kicker starts a line. |
| `types.ts`      | Obstacle, pickup and ramp type definitions shared by spawner, collision and render.                                                                                                                                                                                                                                                                                                                                                 |

## Rules

- Imports only `../core`. Never the DOM, `window`, storage, audio, `render/` or `state/`.
- No `Math.random`, `Date.now` or any time source. Use `core/rng.ts` streams.
- Any rule change must keep `tests/sim.test.ts` and `tests/spawner.test.ts` green. The world fingerprints in `tests/spawner.test.ts` must never be refreshed casually: a changed course breaks shared seed links and per-seed boards.
- Same seed gives the same course in every browser: everything the spawner computes, including `cruiseSpeed` and `topSpeed` in `speed.ts`, uses `core/detMath.ts` or exact operations (`+ - * /`, `round`, `floor`, `min`, `max`, `abs`). Never use `Math.exp`, `sin`, `pow` and the like in that path.
- Flip naming: code comments and signs call positive pitch a backflip, but `flipName` in `score.ts` deliberately shows the opposite on screen: positive is "FRONTFLIP" and negative is "BACKFLIP". Only the displayed text is swapped.
- Rider physics keeps `Math.*` (`sin`, `cos`, `exp`, `atan2`), deliberately. The course cannot depend on it: `Spawner` takes only a seed and a target y, never rider state, and the only rider code it reaches is `speed.ts` (`cruiseSpeed`, `topSpeed`, `airTime`, `maxFlightPx`), which is exact. Math.* in `rider.ts`, `tricks.ts` and `pose.ts` cannot reach the course. A full run is repeatable in one engine but not guaranteed bit-identical across browsers, and nothing needs that since the ghost was removed. If a feature ever replays a run across devices, this has to change first.
- `tests/e2e/course.spec.ts` proves the course guarantee in real Chromium, Firefox and WebKit. Any new spawner code runs under it, so a non-exact call in that path fails the suite.
- `spawner.ts` imports `speed.ts`, never `rider.ts`, `tricks.ts` or `pose.ts`. Keep it that way: it is what keeps the course path exact.
- Jumps are planned from the `config.ts` spacing: the next lip is `JUMP_GAP_MIN`-`JUMP_GAP_MAX` (300-380 px) plus up to `JUMP_JITTER` past the end of the last jump's clear ground, about every 85 m. Jumps and risk lanes are planned together, in order down the slope (`planFeatures`), so a lane that falls due is fitted into the gap before the next jump, `LANE_JUMP_PAD` clear of both, and the jump moves down past it only if the gap is too short; neither is dropped for the other (a lane is still dropped when no side has room). Fairness rules, checked in `tests/spawner.test.ts` and `tests/lines.test.ts`: a solid-free landing zone across the whole slope sized for top speed plus `LANDING_MARGIN`; no jump shares ground with a risk lane; the next lip is always at least `JUMP_GAP_MIN` past the last landing zone, so the gap between lips is always longer than the landing zone before it; a kicker is never wider than the open path.
- Jump lines (`Ramp.line`, `lineIdx`, `lineLen`): 2 or 3 kickers, never before `LINE_START_M`, with the same x (the first one's path centre) and width. Each lip is `LINE_RUNUP_MIN`-`MAX` past the previous kicker's full top-speed landing zone, and every kicker but the last has `landEnd` at the next lip, so the whole line is solid-free across the slope and its later kickers may sit off the open path. The clear ground after the last one runs on (`lineReturnEnd`) until a rider who touched down at the far end of the landing on the line's x can be back inside the open path (turn in over 40 px, then 0.5 px sideways per px downhill, 10 px of the path's half width kept for his body). A bot taking every kicker at top speed never crashes (`tests/lines.test.ts`).
- Stance: `RiderState.stance` is 1 regular or -1 switch, and every run starts regular. A clean or sloppy landing after an odd number of half turns swaps it (a bail does not). It changes only how the rider is drawn: steering, collisions and the board's track are the same either way, and the half-turn speed bonus (+10 instead of +16) still depends on the spin, not the stance. `LandEvent.switch` is true when the rider rides away switch. A spin keeps the takeoff stance in its pose all the way round, so the frame it ends on already shows the side he lands on.
- Grabs: `SimInput.grab` is held, not pressed. While it is true in the air, `stepGrab` adds to `grabT` (every grab of the jump adds up) and emits one `grab` event when it reaches `GRAB_MIN` (0.15 s); on the snow it does nothing, and `launch` and `touchDown` clear it. Still grabbing at touchdown is sloppy (`LandEvent.held`), or a bail after any flip or a spin of `GRAB_BAIL_SPIN` (540) or more. A clean landing pays `grabPoints` (20 at `GRAB_MIN`, plus 100 a second) plus `GRAB_COMBO` (half) of the spin and flip points landed with it, all times the speed multiplier, and counts one trick. `LandEvent.grab` is the seconds paid for, 0 when none. A grab never changes the flight path.
- Import each name from the file that defines it. There is no barrel file.

## Keeping docs in sync (mandatory)

When you change anything in this folder (add, remove, rename a file, change an exported function, constant or rule), update this file in the same change. Update the root `CLAUDE.md` too if the layout or dependency rules move, and `README.md` if player-facing behavior or paths change.
